# H Memo 웹앱 편집 복구 및 유휴 자동 백업 구현 계획

작성일: 2026-07-24

## 목표

- Web Locks API를 지원하지 않는 PC·휴대폰·태블릿 브라우저에서도 메모 조회·생성·수정·삭제가 가능하게 한다.
- 메모 변경은 브라우저 로컬 저장소에 즉시 반영한다.
- 로그인 상태에서 마지막 변경 후 10초 동안 추가 변경이 없을 때 Firebase 백업을 정확히 한 번 실행한다.
- 같은 내용에 대해서는 추가 자동 백업을 실행하지 않는다.
- 자동 백업 직전에 서버의 최신 스냅샷을 다시 확인하여, 다른 기기가 만든 더 최신 스냅샷이 있으면 자동 덮어쓰기를 중단한다.
- 로그인 후 최신 서버 백업 존재 여부를 확인하고, 로컬에 활성 메모가 없을 때 최신 백업을 자동으로 불러온다.
- 기존 수동 백업·복원과 백업 이력 기능은 유지한다.

## 저장 알고리즘

1. 사용자의 메모 생성·수정·삭제·열기·닫기를 로컬 저장소에 즉시 저장한다.
2. 클라우드에 영향을 주는 변경이 발생할 때마다 기존 자동 백업 타이머를 취소하고 10초 타이머를 새로 시작한다.
3. 10초 동안 추가 변경이 없으면 로컬 저장 큐가 끝날 때까지 기다린다.
4. 현재 메모 전체의 안정적인 지문을 계산한다.
5. 마지막 성공 백업 지문과 같으면 Firebase 호출 없이 종료한다.
6. 서버 최신 스냅샷 ID가 이 브라우저가 마지막으로 확인한 ID와 다르면 충돌로 판단하고 자동 백업을 중단한다.
7. 충돌이 없으면 기존 `backupMemos` API로 스냅샷을 한 번 저장한다.
8. 성공 시 새 스냅샷 ID와 지문을 기준값으로 기록한다.
9. 저장 실패 시 반복 호출하지 않고 상태만 표시한다. 사용자가 다시 수정하면 새로운 10초 타이머가 시작된다.

## 구현 구조

- `apps/web/src/webAutoBackup.ts`
  - 메모 지문 계산
  - 10초 유휴 타이머 관리
  - 중복 백업 방지
  - 서버 스냅샷 기준값과 충돌 검사
- `apps/web/src/WebApp.tsx`
  - Web Locks가 없을 때 같은 탭 저장 큐로 로컬 쓰기 허용
  - 자동 백업 컨트롤러 연결
  - 로그인 시 최신 서버 스냅샷 확인
  - 로컬 활성 메모가 없을 때 최신 서버 백업 자동 복원
- `apps/web/src/webAutoBackup.test.ts`
  - 10초 전에 백업하지 않음
  - 추가 수정 시 타이머 재시작
  - 10초 무변경 후 한 번만 백업
  - 같은 지문은 재백업하지 않음
  - 서버 스냅샷 변경 시 충돌로 중단
- `apps/web/src/WebApp.test.tsx`
  - Web Locks 없이 생성·편집 가능
  - 로그인 상태에서 10초 유휴 후 자동 백업
  - 추가 변경이 없으면 재백업하지 않음
  - 로컬 메모가 없을 때 최신 서버 백업 자동 불러오기

## 안전 범위

- 기존 Firestore 백업 스키마와 보안 규칙은 변경하지 않는다.
- 자동 백업은 현재 스냅샷 기반 API를 사용한다.
- 메모 단위 실시간 동기화는 별도 대규모 마이그레이션으로 남기며, 이번 변경에서는 기존 백업 데이터와의 호환성을 우선한다.
- Web Locks가 있으면 기존 다중 탭 잠금을 사용하고, 없으면 같은 탭 안의 Promise 큐로 로컬 저장 순서를 보장한다.
