# 시작 시 메모 비교 안정화와 수동 업데이트 확인

- 작성일: 2026-10-12
- 범위: 시작 시 서버 메모 비교 개선, 메뉴의 프로그램 업데이트 확인 추가, 삭제 없는 업데이트 가능 여부 검토
- 커밋·푸시·배포와 실제 설치 실행은 이번 구현에 포함하지 않습니다.

## 확인한 문제

1. 데스크톱 시작 비교가 최신본 전용 API 대신 보존 기간과 기기 현재 시각에 영향을 받는 백업 기록 페이지를 조회합니다. 기존 `loadLatestBackupSnapshotSummary`를 사용하도록 연결합니다.
2. 시작 확인 실패 시 ref만 초기화하므로 effect가 다시 실행되지 않는 경우가 있습니다. 서비스 미준비도 확인 완료로 처리합니다. 유한 재시도, 온라인 복귀 및 사용자가 선택하는 재확인 경로를 제공하고 오류·충돌 상태를 명확히 안내합니다.
3. 복원 동의 후 재비교에서 알 수 없는 상태를 ready로 처리하는 경로와 계정 변경·언마운트 중 비동기 결과의 유효성을 검토합니다. 불확실한 상태에서는 자동 백업이나 복원으로 서버·로컬을 덮어쓰지 않습니다.
4. 프로그램 updater는 이미 존재하지만 자동 확인만 있고 오류를 숨깁니다. 수동 확인은 재안내 기간을 우회하고 최신 버전·확인 실패·설치 가능 상태를 구분합니다.
5. Windows release workflow에 latest.json 생성 전 존재 검사가 있어 새 릴리스 게시를 막을 수 있습니다. 생성 후 검증으로 수정하고 회귀 검증합니다.

## 구현 방식

- 실제 구현은 gpt-6-luna 하위 에이전트에 위임하고 상위 에이전트가 검토합니다.
- 동기화 상태·재시도 로직과 updater 제어/UI는 기능별 파일로 분리하며 새 파일은 500줄 미만으로 유지합니다. 이미 큰 App.tsx에는 연결 코드만 최소 변경합니다.
- 메모 다운로드는 명시적 동의와 기존 복원 안전장치를 유지합니다. 서로 다른 로컬·서버 변경을 시간만으로 강제로 덮어쓰지 않습니다.
- 프로그램 업데이트 확인과 서버 메모 다시 확인을 구분합니다. 업데이트 확인은 중복 요청 및 설치 중 실행을 차단합니다.
- 데스크톱과 웹 랜딩의 업데이트 내역을 함께 갱신합니다. 버전은 수동 변경하지 않습니다.
- VoiceOver 구현과 검증은 제외합니다.

## 검증

- 최신본 조회, 실패 후 재시도, 계정 변경·언마운트, 중복 확인, 복원 재검증과 충돌 보호 회귀 테스트
- 수동 업데이트 확인의 최신/새 버전/오류/재시도/재안내 우회/설치 차단 테스트
- 업데이트 내역 일치, workflow manifest 순서, 버전 정합성, typecheck, 전체 테스트, build
- 로컬 UI 확인 링크 제공. Windows 실제 업그레이드·메모 보존 검증과 서명된 릴리스 게시 검증은 별도로 보고합니다.

## 업데이트 판단 기준

기존 Tauri updater의 `downloadAndInstall`과 Windows 서명 아티팩트 배포 구성을 점검하고 공식 문서로 설치 방식을 확인합니다. 설치된 구버전의 updater 포함 여부, MSI/NSIS 설치 형식 및 공개 latest.json 제공 여부를 근거로 삭제 없는 업데이트의 지원 범위를 설명합니다.

## 완료 내용과 검증 결과

- 구현 완료: 시작 비교는 서버 전용 조회로 최신 활성 백업을 확인합니다. 활성 포인터가 없는 기존 백업은 날짜 범위를 제한하지 않고 조회합니다. 기존 백업 저장 경로는 별도로 유지했습니다.
- 실패 시 최초 요청을 포함해 최대 3회 확인하며, 15초 응답 제한과 온라인 복귀·수동 재확인을 제공합니다. 불확실한 상태와 충돌에서는 복원을 중단합니다.
- 시작 비교 중 창 위치 저장을 보류하고 같은 위치·크기는 수정으로 기록하지 않습니다. 계정 변경·언마운트·시간 초과 뒤 늦은 응답을 적용하지 않습니다.
- Windows 데스크톱 메인 창 메뉴에 `업데이트 확인`을 추가했습니다. 수동 확인은 재안내 기간을 우회하며 최신 버전·오류·새 업데이트를 구분합니다. 중복 요청과 복원 중 설치를 막습니다.
- `업데이트 실행`을 선택하면 대기 중인 로컬 저장을 먼저 마칩니다. 저장 실패 시 설치를 중단하고, 설치 중 메인 창의 편집과 서버 작업을 비활성화합니다.
- 데스크톱과 웹 랜딩에 동일한 2026-10-12 업데이트 내역을 추가했습니다.
- Windows 릴리스 workflow의 latest.json 생성 전 존재 검사를 생성 후 검증으로 옮겼습니다.
- 최종 전체 테스트: 79개 파일 통과, 1개 파일 skip / 576개 테스트 통과, 11개 skip.
- 전체 workspace typecheck, 데스크톱·웹 build, 버전 정합성(1.0.8, 8개 항목), diff 공백 검사가 통과했습니다. Vite의 큰 번들 경고는 남아 있습니다.
- ego-browser에서 로컬 앱의 메뉴·업데이트 내역 표시를 확인했습니다. 로컬 미리보기: http://127.0.0.1:5174/ (브라우저 대체 화면이므로 Windows updater 설치 기능은 실행하지 않습니다.)
- 공개 v1.0.8 latest.json, MSI, MSI.sig 응답은 HTTP 200이고 manifest의 서명 값이 공개 sig 파일과 일치했습니다. 공개 manifest는 windows-x86_64만 제공합니다.

삭제 없는 업데이트는 Windows MSI 설치본과 updater를 포함한 구버전에서 지원 가능한 구조입니다. Tauri 공식 문서에서도 다운로드·설치를 지원하며 Windows 설치 시 앱이 종료됨을 설명합니다: https://v2.tauri.app/plugin/updater/

실제 Windows 구버전에서 새 버전으로 업그레이드하는 과정과 메모 보존은 이번 환경에서 검증하지 않았습니다. NSIS에서 MSI로 설치 방식을 바꾸는 경로, macOS 업데이트 배포도 미검증입니다. 이번 변경은 로컬 구현이며 커밋·푸시·배포·버전 증가를 실행하지 않았습니다. 기존 공개 릴리스: https://github.com/WBmaker2/h-memo/releases/tag/v1.0.8

## 후속 승인: 홍보 페이지 갱신과 릴리스

2026-10-12 사용자가 커밋·푸시·배포와 홍보 페이지 내용 갱신을 승인했습니다.

1. 랜딩 본문과 기능 소개에 시작 시 최신 메모 비교, 확인 실패 복구, 메뉴 업데이트 확인과 업데이트 실행 절차를 반영합니다. 실제 검증하지 않은 Windows 메모 보존을 보장하지 않습니다.
2. 수정 후 해당 화면 테스트와 전체 검사 결과를 확인하고, 기존 사용자 미추적 파일은 커밋에서 제외합니다.
3. 최신 origin/main을 확인하고 이번 변경 전용 codex/ 브랜치와 PR로 게시합니다. 성공한 CI 뒤 main에 반영해 자동 patch 증가와 태그·웹·Windows·macOS 내부 테스트 배포를 추적합니다.
4. GitHub Pages 홍보 페이지 본문, 현재 버전, 실제 다운로드 링크, Windows release의 latest.json과 signature 일치 여부를 확인합니다. 실제 Windows 설치 검증은 별도 상태로 유지합니다.

구현·커밋·푸시·릴리스 조작은 gpt-6-luna 하위 에이전트가 담당하며 상위 에이전트가 검토와 결과 확인을 담당합니다.

홍보 페이지 본문 반영 후 전체 테스트 577개 통과·11개 skip, 전체 workspace typecheck와 데스크톱·웹 build를 통과했습니다. ego-browser에서 업데이트 방법과 서버 메모 재확인 안내가 표시되고 가로 넘침이 없음을 확인했습니다. 배포 후 확인은 실제 게시된 페이지와 릴리스 결과를 기준으로 별도 수행합니다.
